# 本轮执行基线（更新至 2026-10-21）

此文记录本聊天中用户最后确认的选择，用于后续开发与需求验收。用户之后明确修改时，以新指令为准。此前审计的问题清单是修改前快照，不是当前实现状态。

## 用户已确认的选择

1. **当前直接使用 close 简化实验。** 暂不要求另设正式盘口运行或拆分两套报告。采用信号后的有效分钟 close，不伪造买一卖一；仍保留已有盘口接口以兼容旧调用。
2. **阈值随时可改。** 不把 0.3% 或 0.4% 写成长期固定门槛。每次通过 JSON `simulation.premium_threshold` 或 CLI `--premium-threshold` 指定比例值；命令行覆盖 JSON。两处未给值时不擅自选值运行。现有双向触发逻辑保留，严格超过才触发。
3. **现金替代先在 T+2 的 14:30 尝试代买卖，再以日终价格处理未成交部分。** 这是用户在本轮 close 实验中新指定的执行时点：申购方向代买、赎回方向代卖，仅在该时点尝试一次，不提前在 T/T+1 执行，也不在 14:31 以后逐分钟重试。完全成交用 14:30 的模拟成交金额；部分成交保留已成交金额，仅剩余数量按 T+2 日终收盘价定价。14:30 缺精确行情或交易规则禁止时，未成交数量同样转入日终定价。该时点不冒充说明书的强制要求。其后仍按已确认口径区分通知和交收：之后首个工作日内发送明细，款项在此后三个工作日内交收；不是 T+3 必然到账。实际到账日未知时保持待交收，不提前释放现金或计算最终结清收益。
4. **六列账本的交易额度取 ETF 腿实际成交额。** 申购为卖出 ETF 金额，赎回为买入 ETF 金额。份数按当日 PCF 最小申赎单位乘单位倍数，不将倍数当作 ETF 份数。
5. **默认通过买入或现金替代组齐申购篮子；信号触发前先检查可完成性。** 当日 PCF 中数量大于零的真实成分股，只要存在既无法买入、又禁止现金替代的股票，就不触发申购套利信号。能买入的禁止替代股票不拦截；允许/必须替代的股票不因无法买入而被此条件拦截；零数量和“申赎现金”虚拟行不参与这条检查。本轮仅新增申购方向买入检查，不自行增加赎回卖出限制。
6. **深市允许替代且无法买入时，按用户选择的当前 close 简化保证金。** 当前分钟精确 close × 替代数量 ×（1＋当日 PCF 申购现金替代溢价比例）。不把 PCF 中的零固定替代金额当作免费替代；行情或比例缺失时不擅自填零发起。保证金一次支付，替代数量进入既有 T+2 14:30 代买、未成交日终定价及实际交收分离流程。该保证金公式的价格是用户研究假设，不冒充说明书的除权调整后 T-1 参考价。
7. **当前实验假设全部订单可以足额组齐，按对应金额交易，暂不模拟组篮异常。** 用户于 2026-10-21 明确替换此前“未组齐后持仓暂停”的当前实验路径。`assume_full_basket_fill=true` 为默认：信号后首个允许分钟，整篮所有入场订单先统一校验，再足额买入及提交申赎；不按每分钟容量或可负担资金缩成部分买单。买入、替代保证金及正预估现金按实际对应金额一次扣账，卖出按完整数量计收入。仍不透支资金、不伪造缺失行情；输入不支持整篮假设时，该轮报错，不产生部分持仓或暂停处置状态。旧式部分成交仅保留为显式 `false` 的独立研究能力，不用于当前默认流程。T+2 基金经理代买卖的既有独立尝试/未成交定价规则不因本项扩大改变。

## 继续有效的要求

- 套利发起、申赎及投资者成交窗口：09:35—11:27、13:00—14:57，包含端点分钟。现金到账事件按已提供的真实时间记录，不套用发起窗口。
- 滚动 60 分钟最多发起一笔；取消每日次数上限；上一笔全部结清后再发起下一笔。
- 当前不加手续费、额外滑点和冲击成本，现金替代必须保留。
- Portfolio 保留时间、申购/赎回、交易额度、ETF 份数、赚钱/亏钱、最终盈亏六列。跨日结果仍归属发起 T 日，实际结清时间单独保留。
- 按发起日期筛选期间总盈亏；仍有未结交易时最终总额为空，保留已结清部分。
- 独立折溢价接口位于 pricing/premium_discount.py。Engine 只校验、排序、分发，不重新定价。
- 正式 report 模块输出 report.html、PnL 图、六列账本和全量逐笔账户账目。不得用临时脚本替代正式能力。
- 0.3% 那轮输出桌面、不覆盖原报告目录属于该次实验交付要求，不修改所有运行的默认输出位置。
- 不把初始资金、每次一单位、单只 159338、历史试跑区间或旧上传授权扩展成永久要求。

## 本次实现与输入限制

- 已合入桌面现存的独立折溢价模块及 TradeRecord，并兼容旧六列输入/导出 API；同时保留生命周期及期间汇总。
- 默认两种 cash lag 均为 null。提供 `cash_payment_dates_path` 的 JSON 行（trade_id、kind、paid_at）后，按对应时间推进现金。没有时间记录就保持未支付。
- 2026-10-21 的 0.2% 后续研究试跑：用户指出此前已有模拟到账规则，因此本轮单独恢复历史研究参数 `cash_substitution_lag=3`、`cash_difference_lag=1`，让策略可连续回放。前者从申赎申请日计算，后者从后续 PCF 确认金额的日期计算，均使用给定交易日历。此设置仅为明确标记的 `explicit_research_lag` 模拟到账，不是实际凭证，也不宣称 T+3 必然真实到账；上一版无实际记录则待交收的结果保留。全局默认参数不因单次试跑被改写。
- 结算工作日历由 `settlement_business_days` 单独提供。不用自然日、星期推算或把交易所日历当作结算工作日历。
- `cash_substitution_pricing_days=2` 只实现普通研究情形。期间个股停牌造成的正常交易日延长、20 日特例、公司行为调整仍需额外历史资料，不能声称已完整复现。
- `cash_substitution_attempt_time="14:30"` 为当前代买卖尝试时点；独立定时回调保证它不依赖常规时钟是否列出该分钟。同一分钟的回调与常规时钟不会重复成交。代买卖只取该分钟精确 close，不回退 14:29 行情。
- T+2 未成交数量单独按精确收盘价估值，缺该价格时保持未定价，不使用更晚价格填补。定价日内的 14:30 尝试和 15:00 剩余估值分别记录，不重复记现金或伪造成投资者成交。
- 14:30 的逐只尝试另存 `substitution_attempts.csv`，记录方向、请求/成交/未成交数量及原因；正式逐笔 HTML 也包含这些记录，日终定价不会覆盖当时失败原因。
- 新增信号拦截细节写入 `signals.csv` 的 `blocked_components` 和 `component_reasons`；深市从实物转现金的股票、数量、close、PCF 比例及保证金写入 `creation_substitutions.csv` 和逐笔 HTML。信号与执行层共用当时交易规则，执行层再次检查以防外部决策绕过。未提供历史涨停盘口/状态时，不能从 close 猜测涨停封单或实际可成交性；显式 assume_tradable 仍按有效行情可交易，已提供的禁买/停牌规则照常生效。
- `assume_full_basket_fill=true` 时投资者订单足额成交，不应用 `max_shares_per_minute`；该容量参数仍作用于 T+2 的基金经理模拟尝试。整篮开仓前先核对全部精确行情、交易/申赎许可和实际足额资金，避免先买部分再因第二只股票或资金问题遗留持仓。信号后的更晚分钟成交约定保持不变。
- 明细发送期限及最迟付款期限是规则约束，不是实际到账凭证。到账发生在本次 Runner 日历之外时，本轮保留待交收；跨非交易日的资金事件支持需要扩展日历调度。
- 非 null 的旧 cash lag 仅作为显式研究覆盖参数保留兼容，报告标记 explicit_research_lag；当前基线和样例默认不启用。
- 阈值只绑定具体试跑：2026-10-20 修正规则时没有新阈值，因此没有沿用旧 0.3% 重跑；2026-10-21 用户随后明确指定本轮用 0.2%（比例 0.002）试跑。其余采用最新整篮与现金待交收基线。旧收益文件保留为历史实验，不冒充新规则结果，也不将本轮 0.2% 固定成永久门槛。
